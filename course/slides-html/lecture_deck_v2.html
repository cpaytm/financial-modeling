LLM 시대의 재무모델링

Excel을 더 빨리 치는 수업이 아니라,
모델링 전에 구조를 더 선명하게 만드는 수업.

① BM 언어화 ② HTML 구조화 ③ Excel 구현
한 문장

좋은 모델은 수식이 복잡한 모델이 아니라 구조가 설명되는 모델이다.

구조가 틀리면 Excel 수식이 아무리 정확해도 모델은 틀린다. 그래서 숫자보다 구조를 먼저 본다.

오늘 3시간

개념은 70분, 나머지는 직접 만든다

슬라이드 강의는 절반 이하. 강의의 절정은 웹 Claude로 모델이 실시간으로 자라는 장면이다.

밀리면 줄이는 순서: 실습 → 라이브 데모 분량 → 개념. 개념①과 Tesla 워크스루는 유지.

문제 제기

Excel에서 바로 시작하면, 구조가 숨는다

전통적 출발점

셀 · 시트 · 수식

· 수식은 많아지지만 논리는 안 보임
· 매출·비용의 공유 드라이버가 숨음
· 검토자는 셀 참조만 따라가다 큰 그림을 놓침
· 투자심사 질문 = 여러 시트 재추적

우리가 바꾸는 것

드라이버 · 구조

· Excel 전에 구조를 먼저 드러냄
· 매출·비용·가정의 연결을 한 화면에서
· 구조에 합의한 뒤에 계산을 구현
· Excel은 발명하는 곳이 아니라 닫는 곳

감사·제출·투자심사용 계산 모델. 같은 입력이면 같은 출력.

역할 분리

LLM은 구조화, 계산은 결정론으로 닫는다

LLM (확률적)

BM 설명 구조화 · 매출/비용 분해 · Q×P / 퍼널 제안 · 기존 Excel 시트 요약 · 누락 드라이버 질문 · D / TREE 초안

결정론 (계산)

숫자 계산 · 회계 연결 · 기간별 수식 전개 · 이자/세금/감가상각 · 과거 실적 정합성 · Excel 최종 산출물

핵심: LLM을 많이 쓰는 게 목표가 아니다. 쓸 곳과 쓰면 안 될 곳을 가르는 것이 핵심. LLM이 만든 숫자는 입력값이 아니라 검토 대상.

HTML이 유용한 이유 ①

BM을 드라이버 트리로 본다

HTML이 유용한 이유 ②

하나의 드라이버가 매출·비용·자본을 함께 흔든다

핵심 질문: Fleet를 늘리면 매출만 늘어나는가, 비용과 자본 부담도 같이 늘어나는가?

HTML이 유용한 이유 ③

가정변수를 모델의 표면으로 끌어올린다

가정변수 패널 (시뮬레이터)

Excel에서 핵심 가정은 특정 셀에 숨어 있다. HTML에서는 슬라이더·토글로 표면에 올린다.

그 순간 모델은 계산 파일에서 토론 가능한 구조물로 바뀐다. 투자심사 질문에 같은 화면에서 즉시 대응.

프레임워크 사실

개념은 9블록, 손으로 채우는 건 사실상 하나

YRS · HIST_N · D 3개만 채우면, TREE · INPUT_KEYS · simCalc · SIM_SECS는 D에서 자동 파생된다.

데모에서 "나머지는 자동으로 채워진다"를 보여주는 것이 오히려 가장 강력한 장면.

라이브 데모 · 진행 방식

웹 Claude(claude.ai)에서, 아티팩트가 곧 브라우저

파일을 로컬에서 열 필요 없다. 채팅 우측 아티팩트 패널이 HTML을 실시간 렌더한다. 대화 한 턴 = 모델 한 번 진화.

사전 준비

진행

라이브 데모 · 표준 프롬프트

D를 채워달라고 할 때, 그대로 복붙

# claude.ai 프로젝트(template.html 업로드됨)에 입력 아래 드라이버 구조로 template.html의 YRS, HIST_N, D 블록만 채워서 완성된 HTML을 아티팩트로 만들어줘. · TREE, INPUT_KEYS, DEFAULTS_S, SIM_SECS, simCalc은 D에서 자동 파생되므로 작성하지 마. · 엔진·UI 코드는 절대 수정하지 마. · 각 노드 desc는 [객관]/[주관]/[외생]/[계산] 태그로 시작해. · 매출=primary.900, 비용=neutral.700, 이익=semantic.profit 색 토큰을 주석으로 표기.

⌨️ 리허설 필수 · template.html(146KB)은 채팅에 붙이지 말고 프로젝트 파일로 업로드 · 응답이 깨지면 미리 받아둔 D 완성본으로 B5 단계로 점프

마무리

"Excel을 얼마나 빨리 치는가"에서
"구조를 얼마나 명확하게 설계하고 검증하는가"로.

좋은 모델의 기준은 계산되는 모델을 넘어 설명되는 모델. HTML은 그 설명 가능성을 확보하는 재무모델의 중간 작업대다.

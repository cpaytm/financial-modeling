# LLM 기반 재무모델링 강의안

이 문서는 이 레포를 강의 교안으로 사용할 때의 기본 흐름입니다. 목표는 Claude나 Codex를 써서 Excel 작업을 자동화하는 것이 아니라, 모델링 전에 사업모델과 추정 구조를 더 명확하게 만드는 방법을 익히는 것입니다.

---

## 1. 강의 한 줄 정의

재무모델링을 Excel에서 바로 시작하지 않고, BM 브리프와 LLM 대화, HTML 인터랙티브 트리를 거쳐 Excel 모델로 완성하는 실무형 모델링 방법론.

---

## 2. 수강자가 배워야 할 관점

좋은 재무모델은 수식이 복잡한 모델이 아니라 구조가 설명되는 모델입니다.

LLM 시대의 모델러에게 중요한 역량은 다음 세 가지입니다.

- 회사의 BM을 드라이버 언어로 번역하는 능력
- LLM과 대화하며 누락, 모순, 과도한 단순화를 잡아내는 능력
- Excel 전에 구조를 시각화하고 검토 가능한 형태로 만드는 능력

이 강의에서 HTML은 웹 개발 산출물이 아닙니다. 분석가의 머릿속에 있는 모델 구조를 눈앞에 꺼내 놓는 도구입니다.

---

## 3. 전체 프로세스

```text
1. BM 브리프 작성
2. LLM과 질의응답으로 드라이버 후보 추출
3. 매출, 비용, B/S, 밸류에이션 구조 분해
4. 객관 가정과 주관 가정 분리
5. HTML 트리 구현
6. 시뮬레이터로 주요 가정 검토
7. Excel 모델로 변환
8. 검증, 설명, 투자 판단에 활용
```

---

## 4. 모듈 구성

| 모듈 | 주제 | 실습 산출물 |
|---|---|---|
| 1 | 전통적 모델링의 한계 | 기존 Excel 모델의 문제점 메모 |
| 2 | BM을 모델링 언어로 바꾸기 | BM 브리프 |
| 3 | LLM과 대화하는 법 | 드라이버 후보 리스트 |
| 4 | 매출 구조 분해 | Q × P 트리 초안 |
| 5 | 비용과 자본 구조 연결 | 비용 드라이버 맵 |
| 6 | HTML 인터랙티브 트리 | 단일 HTML 모델 |
| 7 | 시뮬레이션 설계 | 가정변수와 시나리오 |
| 8 | Excel 모델로 구현 | 실행 가능한 Excel 모델 |
| 9 | 검증과 커뮤니케이션 | 투자심사 설명 자료 |

---

## 5. BM 브리프가 먼저 필요한 이유

LLM에게 “이 회사 모델 만들어줘”라고 하면 대개 그럴듯하지만 평면적인 결과가 나옵니다. 먼저 사람이 사업모델을 써야 합니다.

BM 브리프에는 다음이 들어가야 합니다.

- 고객이 누구인지
- 무엇을 팔고 어떤 단위로 과금하는지
- 매출을 움직이는 Q와 P가 무엇인지
- 비용이 매출과 어떤 드라이버를 공유하는지
- 성장의 병목이 트래픽, 전환율, 공급, 인력, 자본 중 무엇인지
- 과거 실적에서 반드시 맞춰야 하는 숫자가 무엇인지
- 주관적 판단이 들어갈 수밖에 없는 가정이 무엇인지

템플릿은 [templates/bm_brief.md](templates/bm_brief.md)에 있습니다.

---

## 6. LLM 대화가 필수적인 이유

LLM은 모델의 정답을 주는 존재가 아닙니다. 대신 분석가의 생각을 압박하고 정리하는 대화 상대입니다.

좋은 대화는 다음 순서로 진행됩니다.

1. BM 설명을 읽고 매출원을 분해하게 한다.
2. 각 매출원별 Q, P, 전환율, 이용률, 반복 구매 같은 드라이버를 묻는다.
3. 비용 항목이 어떤 매출 드라이버와 연결되는지 찾게 한다.
4. 객관 가정과 주관 가정을 분리하게 한다.
5. 누락된 재무제표 연결 항목을 질문하게 한다.
6. HTML 트리로 표현할 수 있는 노드 구조를 제안하게 한다.
7. 사람이 수정하고 다시 질문한다.

예시 프롬프트:

```text
아래 BM 설명을 재무모델링 관점에서 분해해줘.
목표는 Excel 모델을 바로 만드는 것이 아니라, HTML 트리로 시각화할 드라이버 구조를 만드는 거야.

1. 매출원을 BM별로 나눠줘.
2. 각 매출원을 Q × P 또는 퍼널 구조로 분해해줘.
3. 비용 항목 중 매출 드라이버와 공유되는 항목을 찾아줘.
4. 객관 가정과 주관 가정을 분리해줘.
5. 사람이 추가로 확인해야 할 질문을 정리해줘.
```

---

## 7. HTML을 먼저 만드는 이유

Excel은 계산에는 강하지만 구조를 설명하는 데는 약합니다. 반대로 HTML 트리는 다음에 강합니다.

- 모델의 전체 구조를 한 화면에서 보여준다.
- 노드 단위로 매출, 비용, 이익의 연결을 확인할 수 있다.
- 가정변수를 슬라이더로 조정하며 민감도를 바로 볼 수 있다.
- 투자심사나 내부 리뷰에서 “왜 이 숫자가 나왔는지”를 설명하기 쉽다.
- Excel에 들어가기 전에 논리 오류를 잡을 수 있다.

HTML 단계에서 합의해야 할 것은 숫자의 마지막 자리보다 구조입니다.

---

## 8. 전통적 방식과의 차별점

| 질문 | 전통적 방식 | LLM + HTML 방식 |
|---|---|---|
| 모델은 어디서 시작하나 | Excel 파일 | BM 설명 |
| 로직은 어디에 숨어 있나 | 셀 참조와 시트 구조 | 트리 노드와 드라이버 설명 |
| 검토자는 무엇을 보나 | 수식과 출력표 | BM, 드라이버, 가정, 결과의 흐름 |
| LLM은 무엇을 하나 | 일부 수식 작성 | 질문, 구조화, 누락 탐지 |
| 오류는 언제 발견되나 | Excel 완성 후 검토 | HTML 구조화 단계 |
| 시나리오는 어떻게 보나 | 별도 시트와 데이터 테이블 | 인터랙티브 시뮬레이터 |
| 최종 산출물은 무엇인가 | Excel | HTML로 검토된 Excel |

## 9. 실습 과제

### 과제 1. BM 브리프 작성

수강자는 자신이 아는 회사 하나를 골라 [templates/bm_brief.md](templates/bm_brief.md)를 채웁니다. 숫자가 완벽할 필요는 없습니다. 중요한 것은 돈 버는 방식과 드라이버를 말로 설명하는 것입니다.

강사는 먼저 [html-examples/kcar-2023/bm_model_structure.md](../html-examples/kcar-2023/bm_model_structure.md)를 예시로 보여줍니다. 이후 LLM과 직접 대화하면서 framework HTML의 각 블록이 채워지는 과정을 라이브로 시연합니다. 실제 대화 예시는 강의 후 별도 파일로 축적합니다.

### 과제 2. LLM과 드라이버 구조 만들기

BM 브리프를 LLM에 넣고 매출, 비용, B/S 연결 질문을 반복합니다. 최종적으로 HTML 트리에 들어갈 노드 목록을 만듭니다.

### 과제 3. HTML 트리 만들기

[html-framework/template.html](../html-framework/template.html)을 복사해 `YRS`, `D`, `INPUT_KEYS`, `TREE`, `DEFAULTS_S`, `simCalc`, `SIM_SECS`를 채웁니다.

### 과제 4. Excel 모델로 옮기기

HTML에서 확정한 구조를 Excel 시트로 옮깁니다. 이때 Excel은 새 아이디어를 발명하는 공간이 아니라, 이미 합의된 구조를 계산 가능한 형태로 구현하는 공간입니다.

---

## 10. 평가 기준

좋은 제출물은 다음 기준을 만족합니다.

- BM 설명만 읽어도 매출 구조가 이해된다.
- 매출원이 Q × P 또는 퍼널 구조로 분해되어 있다.
- 비용이 매출 드라이버와 어떻게 연결되는지 설명된다.
- HTML 트리에서 주요 가정변수가 조정 가능하다.
- Excel 모델의 구조가 HTML 트리와 일치한다.
- LLM이 만든 내용을 사람이 검토하고 수정한 흔적이 있다.

---

## 11. 강사가 강조할 점

LLM을 쓰면 모델링이 쉬워지는 것이 아니라, 모델링 전에 해야 할 생각을 더 많이 드러낼 수 있습니다.

가장 중요한 질문은 “이 숫자가 맞나?”보다 먼저 “이 구조가 맞나?”입니다. 구조가 틀리면 Excel 수식이 아무리 정확해도 모델은 틀립니다. 이 레포는 그 구조를 먼저 보고, 고치고, 합의하기 위한 수업 자료입니다.

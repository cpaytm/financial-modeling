# LLM 기반 재무모델링 강의안

- 이 레포를 강의 교안으로 쓸 때의 기본 흐름임
- 목표는 Claude·Codex로 Excel 작업을 자동화하는 게 아님: 모델링 전에 사업모델·추정 구조를 더 명확하게 만드는 법을 익히는 것임

---

## 1. 강의 한 줄 정의

- 재무모델링을 Excel에서 바로 시작하지 않음
- BM 브리프 → LLM 대화 → HTML 인터랙티브 트리 → Excel 모델 순으로 완성하는 실무형 방법론

---

## 2. 수강자가 배워야 할 관점

- 좋은 재무모델 = 수식이 복잡한 모델이 아니라 구조가 설명되는 모델임
- LLM 시대 모델러의 핵심 역량 3가지:
  - 회사 BM을 드라이버 언어로 번역하는 능력
  - LLM과 대화하며 누락·모순·과도한 단순화를 잡아내는 능력
  - Excel 전에 구조를 시각화하고 검토 가능한 형태로 만드는 능력
- HTML은 웹 개발 산출물이 아님: 분석가 머릿속의 모델 구조를 눈앞에 꺼내 놓는 도구임

---

## 3. 전체 프로세스

```text
1. BM 브리프 작성
2. LLM과 질의응답으로 드라이버 후보 추출
3. 매출, 비용, B/S, 밸류에이션 구조 분해
4. 객관 가정과 주관 가정 분리
5. HTML 트리 구현
6. 시뮬레이터로 주요 가정 검토
7. Excel 모델로 변환
8. 검증, 설명, 투자 판단에 활용
```

---

## 4. 모듈 구성

| 모듈 | 주제 | 실습 산출물 |
|---|---|---|
| 1 | 전통적 모델링의 한계 | 기존 Excel 모델의 문제점 메모 |
| 2 | BM을 모델링 언어로 바꾸기 | BM 브리프 |
| 3 | LLM과 대화하는 법 | 드라이버 후보 리스트 |
| 4 | 매출 구조 분해 | Q × P 트리 초안 |
| 5 | 비용과 자본 구조 연결 | 비용 드라이버 맵 |
| 6 | HTML 인터랙티브 트리 | 단일 HTML 모델 |
| 7 | 시뮬레이션 설계 | 가정변수와 시나리오 |
| 8 | Excel 모델로 구현 | 실행 가능한 Excel 모델 |
| 9 | 검증과 커뮤니케이션 | 투자심사 설명 자료 |

## 5. BM 브리프가 먼저 필요한 이유

- LLM에게 바로 “이 회사 모델 만들어줘”라고 하면 그럴듯하지만 평면적인 결과가 나옴
- 먼저 사람이 사업모델을 써야 함
- BM 브리프에 들어갈 항목:
  - 고객이 누구인지
  - 무엇을 팔고 어떤 단위로 과금하는지
  - 매출을 움직이는 Q와 P가 무엇인지
  - 비용이 매출과 어떤 드라이버를 공유하는지
  - 성장의 병목이 트래픽·전환율·공급·인력·자본 중 무엇인지
  - 과거 실적에서 반드시 맞춰야 하는 숫자가 무엇인지
  - 주관적 판단이 들어갈 수밖에 없는 가정이 무엇인지
- 템플릿: [templates/bm_brief.md](templates/bm_brief.md)

---

## 6. LLM 대화가 필수적인 이유

- LLM은 모델의 정답을 주는 존재가 아님
- 분석가의 생각을 압박하고 정리하는 대화 상대임
- 좋은 대화 순서:
  1. BM 설명을 읽고 매출원을 분해하게 함
  2. 각 매출원별 Q·P·전환율·이용률·반복 구매 같은 드라이버를 물음
  3. 비용 항목이 어떤 매출 드라이버와 연결되는지 찾게 함
  4. 객관 가정과 주관 가정을 분리하게 함
  5. 누락된 재무제표 연결 항목을 질문하게 함
  6. HTML 트리로 표현할 노드 구조를 제안하게 함
  7. 사람이 수정하고 다시 질문함

예시 프롬프트:

```text
아래 BM 설명을 재무모델링 관점에서 분해해줘.
목표는 Excel 모델을 바로 만드는 것이 아니라, HTML 트리로 시각화할 드라이버 구조를 만드는 거야.

1. 매출원을 BM별로 나눠줘.
2. 각 매출원을 Q × P 또는 퍼널 구조로 분해해줘.
3. 비용 항목 중 매출 드라이버와 공유되는 항목을 찾아줘.
4. 객관 가정과 주관 가정을 분리해줘.
5. 사람이 추가로 확인해야 할 질문을 정리해줘.
```

---

## 7. HTML을 먼저 만드는 이유

- Excel은 계산에 강하지만 구조 설명에 약함
- 반대로 HTML 트리가 강한 점:
  - 모델 전체 구조를 한 화면에서 보여줌
  - 노드 단위로 매출·비용·이익의 연결을 확인함
  - 가정변수를 슬라이더로 조정하며 민감도를 바로 봄
  - 투자심사·내부 리뷰에서 “왜 이 숫자가 나왔는지” 설명이 쉬움
  - Excel에 들어가기 전에 논리 오류를 잡음
- HTML 단계에서 합의할 것은 숫자의 마지막 자리보다 구조임

---

## 8. 전통적 방식과의 차별점

| 질문 | 전통적 방식 | LLM + HTML 방식 |
|---|---|---|
| 모델은 어디서 시작하나 | Excel 파일 | BM 설명 |
| 로직은 어디에 숨어 있나 | 셀 참조와 시트 구조 | 트리 노드와 드라이버 설명 |
| 검토자는 무엇을 보나 | 수식과 출력표 | BM, 드라이버, 가정, 결과의 흐름 |
| LLM은 무엇을 하나 | 일부 수식 작성 | 질문, 구조화, 누락 탐지 |
| 오류는 언제 발견되나 | Excel 완성 후 검토 | HTML 구조화 단계 |
| 시나리오는 어떻게 보나 | 별도 시트와 데이터 테이블 | 인터랙티브 시뮬레이터 |
| 최종 산출물은 무엇인가 | Excel | HTML로 검토된 Excel |

## 9. 실습 과제

### 과제 1. BM 브리프 작성

- 수강자는 자신이 아는 회사 1개를 골라 [templates/bm_brief.md](templates/bm_brief.md)를 채움
- 숫자가 완벽할 필요는 없음: 돈 버는 방식과 드라이버를 말로 설명하는 게 핵심임
- 강사는 먼저 [examples/Tesla/tesla_bm_revenue_methodology.md](../examples/Tesla/tesla_bm_revenue_methodology.md)를 예시로 보여줌
- 이후 LLM과 직접 대화하며 framework HTML의 각 블록이 채워지는 과정을 라이브로 시연함
- 실제 대화 예시는 [examples/Tesla/conversation_transcript.md](../examples/Tesla/conversation_transcript.md)에 있음 (이 전사본 자체가 실전 사례임)

### 과제 2. LLM과 드라이버 구조 만들기

- BM 브리프를 LLM에 넣고 매출·비용·B/S 연결 질문을 반복함
- 최종적으로 HTML 트리에 들어갈 노드 목록을 만듦

### 과제 3. HTML 트리 만들기

- [framework/template.html](../framework/template.html)을 복사함
- `YRS`/`HIST_N`/`MODEL`를 채움 (`TREE`·`INPUT_KEYS`·`DEFAULTS_S`·`simCalc`·`SIM_SECS`는 `MODEL`에서 자동 파생됨)

### 과제 4. Excel 모델로 옮기기

- HTML에서 확정한 구조를 Excel 시트로 옮김
- Excel은 새 아이디어를 발명하는 공간이 아님: 이미 합의된 구조를 계산 가능한 형태로 구현하는 공간임

## 10. 평가 기준

- 좋은 제출물의 기준:
  - BM 설명만 읽어도 매출 구조가 이해됨
  - 매출원이 Q × P 또는 퍼널 구조로 분해됨
  - 비용이 매출 드라이버와 어떻게 연결되는지 설명됨
  - HTML 트리에서 주요 가정변수가 조정 가능함
  - Excel 모델의 구조가 HTML 트리와 일치함
  - LLM이 만든 내용을 사람이 검토·수정한 흔적이 있음

---

## 11. 강사가 강조할 점

- LLM을 쓰면 모델링이 쉬워지는 게 아님: 모델링 전에 해야 할 생각을 더 많이 드러내게 됨
- 가장 중요한 질문: “이 숫자가 맞나?”보다 먼저 “이 구조가 맞나?”
- 구조가 틀리면 Excel 수식이 정확해도 모델은 틀림
- 이 레포는 그 구조를 먼저 보고·고치고·합의하기 위한 자료임

---

## 12. 3시간 강의 타임테이블

- 총 180분 기준
- 개념 강의는 60~75분이면 충분: 나머지 시간은 데모·실습으로 채움
- 강의의 핵심: “산출물이 대화를 따라 같이 바뀌는 장면”을 직접 보여주는 것(§11)

| 1. 개념 (슬라이드 01~02) | 10–45분 | 45 | 파일 하나와 MODEL 객체 → 노드 스키마 → 그래프 구조와 공유 드라이버 | 슬라이드 01 구조, 02 그래프 |
| 2. 개념 (슬라이드 03~04) | 45–70분 | 70 | 작업 흐름과 breakdown 기준 → 자동 검증 → Excel과의 역할 구분 | 슬라이드 03 작업 흐름, 04 Excel 비교 |

- 수강생 노트북에 Claude/Codex 접근 환경을 강의 전 안내함(실습 블록 전제)

## 13. 라이브 데모 진행 대본

- 데모의 목적은 “완성된 모델 자랑”이 아님: 대화 한 턴마다 BM md와 HTML이 같이 바뀌는 장면을 보여주는 것임(§11)

> **프레임워크 사실(중요):** 현재 `framework/template.html`은 강사가 직접 채우는 블록이 **`YRS` / `HIST_N` / `MODEL` 3개뿐**임. `TREE` · `INPUT_KEYS` · `DEFAULTS_S` · `SIM_SECS` · `simCalc()`는 `MODEL`에서 **자동 파생됨**([framework/html_framework.md](../framework/html_framework.md)). 실제로 손으로 채우는 것은 사실상 **`MODEL` 하나**임. 데모 중 “나머지는 자동으로 채워짐”을 보여주는 게 오히려 강력한 장면임.

### 진행 대본 A: 데모 ①: Tesla 전사본 워크스루 (해설형, 30분)

- 준비물: [examples/Tesla/conversation_transcript.md](../examples/Tesla/conversation_transcript.md)(43턴), `tesla_bm_revenue_methodology.md`, `tesla_revenue_model.html`을 미리 띄워 둠

진행:
1. **(3분) 출발점**: 전사본 1~3턴. 사용자가 준 BM 설명과, Claude가 “매출 − 비용 = 영업이익”으로 골격을 잡는 장면
2. **(7분) 매출원 분해**: 6~7턴. ①Automotive / ②Energy(`Q=배포 GWh, P=$/kWh`) / ③Services를 Q×P로 쪼개는 과정. 객관/주관 태그가 어떻게 갈리는지 강조
3. **(7분) 결정론적 확정**: 12~15턴. 근사치였던 차량판매/리스 분할을 10-K 원문으로 확정하고 6개년 reconcile을 통과시키는 장면. “사람이 LLM 근사치를 그대로 두지 않고 공시값으로 확정한다”가 핵심
4. **(8분) 구조 → 화면**: 16~19턴. 합의된 구조가 `tesla_revenue_model.html`의 트리·시뮬레이터로 나타나고, 차량판매가 3개 모델 PQ로 세분화되는 장면. 슬라이더를 직접 움직여 봄
5. **(5분) 검증**: 40~41턴. HTML↔Excel 200셀 대사 오차 0을 보여주고 마무리

- 폴백 가치: 이 전사본은 라이브 데모 ②가 깨졌을 때 그대로 대체 가능한 완결 자료임

### 진행 대본 B: 데모 ②: Tesla 라이브 빌드 (Automotive, 실시간, 40분)

- 준비물: claude.ai 프로젝트에 `framework/template.html`과 `examples/Tesla/tesla_bm_revenue_methodology.md`를 업로드, LLM 세션, 미리 받아둔 `MODEL` 완성본(폴백)

진행(각 단계 = 대화 1~2턴 + 화면 확인):

| 단계 | 시간 | 강사 행동 | 보여줄 화면 |
|---|---|---|---|
| B1 | 5분 | Tesla 매출을 세그먼트로 분해 요청 | LLM이 Automotive/Energy/Services로 가른 응답 |
| B2 | 8분 | Automotive를 Q×P로 분해 요청(인도량 × ASP, 리스·규제크레딧 분리) | 드라이버 트리 텍스트 |
| B3 | 7분 | 공유 드라이버 찾기 요청(인도량 → 차량판매·서비스 매출 + 변동원가·보증·물류) | 매출·비용 교차 참조 표 |
| B4 | 10분 | “이 구조로 `template.html`의 **`YRS`/`HIST_N`/`MODEL`**만 채워 아티팩트로 만들어줘. 엔진은 건드리지 마” | LLM이 `MODEL` 객체 작성 |
| B5 | 7분 | 아티팩트 렌더 확인 | **트리·가정변수표·시뮬레이터가 자동 생성**되는 장면 |
| B6 | 3분 | 슬라이더로 점유율·ASP 흔들기 → 영업이익 반응 | 인터랙티브 시뮬레이션 |

표준 프롬프트(B4용, 그대로 사용 가능):

```text
아래 드라이버 구조로 framework/template.html의 YRS, HIST_N, MODEL 블록만 채워줘.
- TREE, INPUT_KEYS, DEFAULTS_S, SIM_SECS, simCalc은 MODEL에서 자동 파생되므로 작성하지 마.
- 엔진·UI 코드는 절대 수정하지 마.
- 각 노드 desc에 이 숫자의 근거를 한 문장으로 적어줘.
- 매출은 primary.900, 비용은 neutral.700, 영업이익은 semantic.profit 색 토큰을 주석으로 표기해.
```

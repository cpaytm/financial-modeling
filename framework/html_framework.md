# Framework — 캔버스 + 계정 트래킹 셸

[template.html](template.html)은 인터랙티브 트리 엔진에
**좌측 사이드바 + 계정별 문서 뷰**를 얹은 단일 HTML 산출물이다.

회사별로 채우는 블록은 **`YRS` / `HIST_N` / `MODEL`** 세 개뿐이다.
사이드바·계정 페이지·가정변수표·검증 항목은 전부 `MODEL`에서 자동 파생된다.

---

## 화면 요약

| | |
|---|---|
| 화면 | 사이드바 + (캔버스 \| 계정 페이지) |
| 전체 조망 | 캔버스 + 요약 대시보드 |
| 요소 추적 | 사이드바 트리에서 값까지 상시 노출 |
| 계정 상세 | 전용 페이지 (추이 · 분해 · 근거 · 드라이버 · 영향도) |
| 가정변수 | 모달 + `가정·근거` 페이지 + 페이지 내 직접 입력 |
| 검증 | `검증·이슈` 페이지 (6개 자동 점검) |
| 시뮬레이터 | 우측 패널 (계정 페이지와 동시 사용 가능) |
| 엑셀/JSON export | 지원 |

---

## 사용법

```bash
cp framework/template.html examples/<회사명>/index.html
# 편집기로 열어 ★ 블록 1(YRS/HIST_N)과 ★ 블록 2(D)를 채운다
open examples/<회사명>/index.html
```

파일 상단 `<html data-model-id="...">`는 브라우저 localStorage 키다.
회사별로 다른 값을 주면 편집 상태가 서로 섞이지 않는다.

사이드바 브랜딩은 `#brandLogo` / `#brandName` / `#brandSub` /
`#footTitle` / `#footSub` 다섯 군데만 고치면 된다.

## 화면 구성

### 좌측 사이드바 — 요소 트래킹

- **Overview** — 전체 캔버스 / 요약 대시보드
- **계정 트리** — `MODEL`의 parent 관계를 그대로 펼친 트리. 각 행 오른쪽에
  **최종 연도의 값**이 붙는다. 캔버스의 `openSet`과 펼침 상태를 공유하므로
  캔버스에서 접으면 사이드바도 접힌다.
  - 막대 표시 = 계산 노드, 점 표시 = 가정변수(입력)
- **Model control** — 가정·근거 / 전체 테이블 / 검증·이슈

사이드바 값 칩과 표의 비중 열은 **모델 최종 연도** 기준이다.
사이드바 `계정 트리` 캡션에 그 연도와 실적/추정 여부가 표시된다.

### 전체 캔버스 (전체 조망)

드래그·줌 트리. 노드 조작:

- 노드 선택 후 **계정 열기** → 해당 계정 페이지로 이동
- 계정 페이지의 **캔버스에서 보기** → 그 노드를 펼쳐서 화면 중앙에 정렬

### 계정 페이지

`MODEL`의 노드 하나당 한 페이지. 자동으로 만들어진다.

- **추이 차트** — 자식이 있으면 자식별 누적, 없으면 단일 막대.
  막대 위에 값이 직접 표시되고, 실적 구간은 회색 배경으로 구분된다.
  (상단 KPI 카드 행은 두지 않는다 — 같은 숫자를 차트가 보여준다.)
- **구성요소 분해** — 자식 × 전 연도 표 + 최종 연도 기여도 막대
- **추정 근거** — `desc` 원문, 계산식, 하위 요소 링크
- **가정변수 직접 입력** (input 노드 한정) — 연도별 숫자 입력.
  값을 바꾸면 모델 전체가 즉시 재계산되고, 초안에서 벗어난 칸은 파란 테두리로 표시된다.
- **연결된 가정변수** — 이 계정을 움직이는 입력 노드와 근거 요약 (수식 의존성 기준)
- **영향받는 계정** — 이 값을 바꾸면 다시 계산되는 노드

### 가정·근거

입력 노드를 부모별로 묶은 표.

### 값 변경의 전파

시뮬레이터 슬라이더, 케이스 전환, 계정 페이지의 직접 입력, 노드 편집, 초안 리셋은
모두 엔진의 `simCalc()`을 거친다. 이 한 지점에 후크를 걸어
**캔버스 · 사이드바 · 열려 있는 계정 페이지 · 전체 테이블 모달 · 가정변수 모달**을
같은 프레임에 다시 그린다 (`refreshSurfaces()`, requestAnimationFrame으로 1프레임 1회).

입력 칸에 커서를 둔 채 값이 갱신돼도 포커스와 커서 위치, 스크롤 위치는 유지된다.

### 검증·이슈

사이드바에 미통과 건수가 표시된다.

| 점검 | 검사 내용 | 미통과 표시 |
|---|---|---|
| 수식 평가 | 파싱·평가 실패 노드 | 실패 |
| 부모 = 자식 합 | 합계형 노드의 자식 합 일치 (상대오차 1e-6) | 실패 |
| 트리 연결 | root에서 도달 불가한 고아 노드 | 실패 |
| 실적 구간 음수 | 실적 연도의 음수 값 | 주의 |
| 미사용 가정변수 | 어떤 수식도 참조하지 않는 입력 | 주의 |
| 초안 대비 변경 | 시뮬레이션·직접입력으로 바뀐 입력 | 주의 |

## MODEL 작성 규칙

```js
node_id:{
  label:'표시명',
  sub:'부제',                       // 선택 — 캔버스 노드 2번째 줄
  parent:'부모 id' | null,          // root만 null
  type:'computed' | 'input',
  formula:'a * b',                  // computed만
  v:[연도별 값],                     // 길이 = YRS.length
  u:'단위',
  desc:'근거 문장.',           // 앞머리 [태그]는 화면에 노출되지 않는다
  pct:1,                            // 비율 표시할 때
  bg:'#1E2185', fg:'#FFFFFF', sfg:'#A1B8FF',   // 캔버스 색 (DS 토큰만)
}
```

수식 문법: `+ - * / ( )` · `SUM/MIN/MAX/AVG(a,b,…)` · `IF(c,t,e)` · `PREV(x)`.
연도별 element-wise 평가. 같은 해 순환참조는 자동 검출된다.

`DEFAULTS_S`는 `MODEL`의 input 노드로부터 자동 파생된다. 손댈 필요 없다.

### 색상

`MODEL[k].c`는 **캔버스 노드 색 전용**이다. 차트·표·사이드바 색은 형제 순서로
DS 램프에서 자동 배정되므로(같은 차트에 그려지는 노드끼리 항상 구분됨)
`c`를 형제끼리 같게 줘도 문제되지 않는다.

램프는 [design-guide/tokens.js](../design-guide/tokens.js) 기준:

- 매출 계열 — `#1E2185` `#3332D0` `#5D68F7` `#7C91FD` `#A1B8FF` `#C5D5FF`
- 비용 계열 — `#374151` `#4B5563` `#6B7280` `#9CA3AF`

노드 id나 label에 `cost` / `비용` / `원가` / `판관비`가 들어가면(또는 조상에 들어가면)
비용 램프로 자동 전환된다. 빨강(`#DC2626`)은 음수 델타에만 쓴다.

## 그래프 색인

`MODEL`에는 엣지가 두 종류 들어 있다.

| 필드 | 만드는 것 |
|---|---|
| `parent` | 집계 트리 — 무엇이 무엇에 속하는가 |
| `formula` | 계산 의존성 — 무엇으로부터 계산되는가 |

`rebuildIndexes()`에서 한 번 색인하고 `childrenOf`/`rootId`/`depthOf`/`pathOf`는
전부 조회로 처리한다. 의존성 색인은 `topoSort()`에 의존하므로 `graphDeps()`로 지연 구축한다.

> **주의** — `simCalc()`은 캐시된 위상정렬 순서를 재사용한다.
> 수식·노드를 바꾼 뒤에는 반드시 `clearFormulaCache()` → `rebuildIndexes()` → `simCalc()`
> 순서를 지켜야 한다. 이 순서를 건너뛰면 계산 순서가 낡은 채로 남아
> **에러 없이 숫자가 조용히 틀어진다.** 편집 경로는 `_afterEdit()` 한 곳으로 모아 두었다.

새로 생기는 것은 **역방향 의존(`dependents`)** 이다. "이 값을 바꾸면 무엇이 흔들리는가"에
답할 수 있다는 뜻이고, 여기서 아래가 파생된다.

```js
driversOf(id)        // 이 계정을 움직이는 가정변수 (트리 하위가 아니라 수식 의존성 기준)
descendantsOf(id)    // 이 값을 바꾸면 다시 계산되는 노드 전부
ancestorsOf(id)      // 이 값을 만드는 데 쓰이는 노드 전부
unusedInputs()       // 어떤 수식도 참조하지 않는 가정변수
sharedDrivers(a,b)   // 두 계정이 함께 물고 있는 가정변수
```

화면:

- 계정 페이지 **영향받는 계정** 카드 — 전파 경로를 계산식과 함께 나열
- **연결된 가정변수**는 트리 하위 스캔이 아니라 수식 의존성 기준이다.
  서브트리 밖에 있는 드라이버(`PREV`, 공유 드라이버)도 잡힌다
- 검증에 **미사용 가정변수** 항목

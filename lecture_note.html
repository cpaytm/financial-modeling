01. 구조

모델 전체가 파일 하나, 데이터는 객체 하나

브라우저에서 바로 열리는 단일 HTML 파일, 서버도 설치도 필요 없음
MODEL 모델 데이터 객체
  • template.html 안의 자바스크립트 객체 이름
  • 모든 계정이 여기 하나에
  • 계정 하나가 객체의 키 하나
const MODEL = {
  sales_3y: {              // 노드 id
    label:   'Model 3/Y 매출',
    parent:  'auto_sales',  // 상위 계정
    type:    'computed',
    formula: 'del_3y * asp_3y', // 다른 노드 id
    v:       [60205, 71965, …], // 연도별 값
    desc:    '인도량 × ASP, 2025 실적 62,007',
  },
  del_3y: { type:'input', u:'천대', … },
}
노드 타입
  • computed 수식으로 계산되는 노드, 값을 직접 못 바꿈
  • input 가정변수, 슬라이더와 입력칸이 자동으로 붙음
수식 문법 + - * / ( ) · SUM MIN MAX AVG · IF · PREV 전년도 참조
직접 채우는 것
YRS연도 배열, 실적을 먼저 쓰고 추정을 뒤에
HIST_N확정 실적 연도 수
MODEL계정과 수식과 값과 근거
MODEL 객체를 읽어 화면을 만드는 방식
엔진이 읽는 것만들어지는 것
parent 필드계정 트리 사이드바와 전체 캔버스
formula 파싱계산 순서를 정하고 연도별로 계산
type가 input인 노드시뮬레이터 슬라이더와 연도별 입력칸
계산 결과 v계정별 페이지, 추이 차트, 구성요소 분해
MODEL 전수 검사어긋난 곳을 찾아 사이드바에 건수 표시
노드 순회Excel 수식 변환과 JSON 내보내기
엔진과 UI는 손대지 않고, 회사가 바뀌면 MODEL 객체만 교체

02. 그래프

MODEL 객체 안에 연결이 두 종류

parent 어느 계정에 속하는지 · formula 어떤 값으로 계산되는지
그래프 노드와 화살표로 이루어진 연결망
  가정변수              계산 노드            상위 계정

  del_3y  ─┐
             ├──▶ sales_3y ──▶ auto_sales ──▶ root
  asp_3y  ─┘
             formula: del_3y * asp_3y
  • 노드 하나가 계정 하나
  • 화살표는 참조 방향
  • 이 화살표를 다 합친 것이 그래프
  • 화살표를 거꾸로 따라가면 이 계정을 움직이는 가정변수가 나옴
두 연결의 차이
parent집계 트리, 하위 합이 상위로 올라감
formula계산 의존성, 참조하는 노드가 먼저 계산됨
둘이 어긋나는 경우는 전년도를 참조하는 스톡 변수, 그리고 매출과 비용이 함께 쓰는 공유 드라이버
그래프 구조가 필요한 이유
계산 순서 자동 결정위상정렬로 참조 순서가 자동으로 정해져 시트 순서를 관리할 필요 없음
순환참조 즉시 검출같은 해에 서로 참조 시 즉시 검출
영향도 목록이 값을 바꾸면 다시 계산되는 계정을 계산식과 함께 표시
드라이버 역추적이 계정을 움직이는 가정변수만 골라냄, 트리가 아니라 수식을 따라감
미사용 가정변수 적발어떤 수식도 참조하지 않는 입력, 오타이거나 삭제 잔재
노드 20개면 손으로도 되지만, 비용과 현금흐름까지 붙어 150개가 넘으면 불가능

계정 breakdown 기준

04. Excel 비교

HTML로 설계하고 Excel로 공유

설계하고 검증하는 쪽은 HTML, 남들과 주고받는 쪽은 Excel
LLM이 할 수 있는 일ExcelHTML
파일 읽기압축된 바이너리라 변환 도구를 거쳐야 함텍스트라 파일만 주면 바로 답변
계정 관계 파악셀 참조를 하나씩 따라가며 추측parent와 formula에 적혀 있음
근거 찾기셀 메모에 흩어져 있음계정마다 근거 문장이 붙어 있음
가정 찾기수식 안 숫자와 구분이 안 됨노드로 선언돼 있어 전부 목록화
바뀐 곳 찾기파일 통째로 비교되어 의미 없음git diff로 바뀐 줄만 확인
권장 순서
1
HTML에서 구조 확정고치기 싸고 LLM과 같이 고칠 수 있음
2
검증 통과 확인수식 오류와 합계 불일치가 없을 때만 다음으로
3
Excel 생성HTML에서 정한 구조 그대로, 값이 아니라 수식으로
4
구조 변경은 HTML에서Excel에서 바로 고치면 둘이 어긋남
LLM에게 바로 물어볼 수 있는 것
  • 이 계정이 어떤 수식으로 계산되는지
  • 이 가정을 바꾸면 어디가 영향받는지
Excel로 공유하는 이유
  • 재무 쪽에서 다들 쓰는 도구, 심사와 실사가 Excel로 돌아감
  • 민감도 표 · 피벗 · 시나리오 비교 기능이 이미 다 있음
  • 내보낸 파일에 수식이 그대로, 값만 붙은 게 아니라 이어서 작업 가능
HTML은 설계와 검증, Excel은 공유

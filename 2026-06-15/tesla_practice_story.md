# 테슬라 실습 스토리 — 웹 Claude로 매출모델 트리 만들기

작성일: 2026-06-15 · 대상: 3시간 강의 라이브 데모 + 수강생 실습
진행 환경: **웹 Claude(claude.ai)** — 로컬 파일 편집 없이 아티팩트로 진행함
준거 자료: [tesla_bm_revenue_methodology.md](../examples/Tesla/tesla_bm_revenue_methodology.md) · [conversation_transcript.md](../examples/Tesla/conversation_transcript.md) · [template.html](../framework/template.html)

---

## 0. 이 문서의 사용법

- 이 스토리는 **강사의 라이브 데모 대본**이자 **수강생의 실습 가이드**로 동시에 씀
- 한 장면(Scene) = 대화 1~2턴. 각 장면은 `입력 → 기대 출력 → 확인할 것 → 막히면` 4단으로 구성함
- 숫자·프롬프트는 그대로 복붙 가능하게 적음. 실제 응답은 매번 조금씩 다르므로 **확인할 것**에 집중함
- 목표는 완성된 모델 자랑이 아니라, **대화 한 턴마다 트리가 자라는 장면**을 직접 보는 것임

---

## 1. 목표

- 테슬라 매출(Automotive · Energy · Services)을 **Q×P 드라이버 트리**로 분해함
- 공유 드라이버(인도량)가 매출·비용에 동시에 연결되는 구조를 확인함
- `template.html`의 **`YRS` / `HIST_N` / `D` 3개 블록만** 채워 인터랙티브 트리를 아티팩트로 띄움
- 슬라이더로 가정을 흔들어 영업이익 반응을 봄

> 손으로 채우는 건 사실상 `D` 하나임. `TREE` · `INPUT_KEYS` · `simCalc` · `SIM_SECS`는 `D`에서 자동 파생됨.

---

## 2. 준비물 (강의 전 세팅)

- claude.ai에 **프로젝트 1개** 생성함
- 프로젝트 파일로 업로드함 (채팅창에 붙여넣지 않음 — 토큰 낭비·깨짐 방지):
  - `framework/template.html` (146KB 스켈레톤)
  - `examples/Tesla/tesla_bm_revenue_methodology.md` (테슬라 매출 설계도)
- **D 완성본을 미리 1회 생성해 따로 저장함** (폴백용)
- `examples/Tesla/conversation_transcript.md`를 탭에 띄워 둠 (최종 폴백)
- 디자인 토큰 규칙을 미리 안내함: 매출=`#1E2185`, 비용=`#374151`, 이익=`#22C55E`, 입력변수=`#5D68F7`

## 3. 실습 스토리 (Scene 0 → 7)

### Scene 0. 세팅 확인 (2분)

- 프로젝트에 `template.html`과 테슬라 methodology가 올라가 있음을 보여줌
- "오늘은 이 두 파일만 가지고, 채팅으로 매출 트리를 키울 것"이라고 한 줄로 잡음

---

### Scene 1. 매출원 3분해 (5분)

**입력**

```text
프로젝트에 올린 테슬라 매출 설계도를 기준으로,
테슬라 총매출을 최상위 세그먼트로 나눠줘.
각 세그먼트의 FY25 매출과 비중도 같이 표로 정리해줘.
아직 Q×P로는 쪼개지 마.
```

**기대 출력**

- Automotive ≈ $69.5B (73%) / Energy ≈ $12.8B (13%) / Services & Other ≈ $12.5B (13%)
- 총매출 ≈ $94.8B (FY25)

**확인할 것**

- 3세그먼트 합이 총매출과 맞는지 봄 (reconcile)
- Automotive가 전체의 ~73%로 가장 큰 세그먼트인지 확인함
- 매출 방향이 엇갈림(자동차 둔화 ↔ 에너지 급성장)을 짚음 → 합계가 아닌 **구성요소 단위 추정**이 필요한 이유임

**막히면**

- 비중이 안 맞으면 "FY25 라인아이템 기준으로 다시 reconcile해줘"라고 되물음

---

### Scene 2. Automotive를 Q×P로 분해 (8분)

**입력**

```text
Automotive를 Q×P로 재귀 분해해줘.
- 차량판매 = 인도량 × ASP 로 두고, 인도량은 Model 3/Y · S/X+Cybertruck · 신차로 나눠줘
- 리스와 규제크레딧은 별도 라인으로 분리해줘
각 리프 노드에 [객관]/[주관]/[외생] 태그를 붙이고, 주관 항목은 상/하한 시나리오로 표시해줘.
```

**기대 출력**

- `automotive_sales = Σ(deliveries_model × asp_model)`
- `deliveries_model3y` [주관·수요제약] = EV시장 × 점유율
- `regulatory_credits` [주관·외생] — Q×P 분해 안 함, 정책 step-down
- 생산능력 상한(`production_capacity` [객관])으로 수요 캡 체크

**확인할 것**

- 인도량과 ASP가 **섞이지 않고** Q·P로 분리됐는지 봄
- 규제크레딧을 Q×P로 억지 분해하지 않았는지 봄 (외생 라인으로 빠져야 함)
- "[주관]은 상/하한 먼저"가 지켜졌는지 확인함

**막히면**

- ASP를 그냥 한 숫자로 두면 "기준가 − 인센티브 ± 믹스 ± FX로 분해 근거를 적어줘"라고 압박함

---

### Scene 3. 공유 드라이버 식별 — 인도량 (7분) ★핵심

**입력**

```text
지금 만든 매출 구조에서, 하나만 바꿔도 여러 곳이 동시에 움직이는 공유 드라이버를 찾아줘.
특히 인도량(deliveries)이 매출과 비용 양쪽에서 어디에 연결되는지 표로 정리해줘.
```

**기대 출력**

| 공유 드라이버 | 매출 측 | 비용 측 |
|---|---|---|
| 인도량 | 차량판매 매출, 서비스 매출(보유대수↑) | 배터리·부품 변동원가, 보증 충당, 물류비 |
| ASP | 차량판매 매출 | 단위 마진(가격인하 시 GPM 압박) |
| 규제크레딧 | 매출(+영업이익) | 대응원가 ≈ 0 |

**확인할 것**

- 인도량을 **①에서 한 번만 추정**하고, 서비스·ASP믹스가 이를 **참조**하는 단방향 구조인지 봄
- 같은 드라이버를 두 곳에서 따로 가정하지 않는지 확인함 (이중 가정 금지)
- 이 장면이 "Excel 여러 시트에 흩어진 참조를 한 화면에서 본다"의 핵심임을 강조함

**막히면**

- 비용 측이 비면 "비용은 별도 문서지만 공유 드라이버는 지금 못박아야 한다"고 §7 원칙을 상기시킴

---

### Scene 4. `D` 블록 채우기 (10분)

**입력 (표준 프롬프트 — 그대로 복붙)**

```text
지금까지 합의한 테슬라 매출(Automotive·Energy·Services) 구조로
프로젝트의 template.html에서 YRS, HIST_N, D 블록만 채워서
완성된 HTML을 아티팩트로 만들어줘.

· TREE, INPUT_KEYS, DEFAULTS_S, SIM_SECS, simCalc은 D에서 자동 파생되므로 작성하지 마.
· 엔진·UI 코드는 절대 수정하지 마.
· 인도량은 한 번만 추정하고 ASP·서비스가 참조하도록 formula로 연결해.
· 각 노드 desc는 [객관]/[주관]/[외생]/[계산] 태그로 시작해.
· 매출=#1E2185, 비용=#374151, 이익=#22C55E 색 토큰을 주석으로 표기해.
```

**기대 출력**

- `YRS = [2020 … 2025, 2026E …]`, `HIST_N = 6` (FY2020~25 실적)
- `D` 객체에 각 노드의 `label · parent · type · formula · v · u · desc`가 채워짐
- 과거 실적값은 methodology §3 라인아이템(확정값)으로 적재됨

**확인할 것**

- 손으로 채운 게 `D` 하나뿐이라는 점을 명시함 (나머지는 비워둠)
- `installed_base = PREV(installed_base) + deliveries_total` 같은 **롤포워드 연결**이 있는지 봄
- 과거 실적이 10-K 확정값인지(파란 입력값), 추정이 수식인지 구분함

**막히면 (가장 위험한 구간)**

- 응답이 깨지거나 엔진을 건드리면 → **미리 받아둔 `D` 완성본을 붙여넣고 Scene 5로 점프함**

---

### Scene 5. 아티팩트 렌더 확인 (7분) ★자동 파생 장면

**입력**

```text
좋아. 이 아티팩트를 그대로 열어서 트리와 시뮬레이터가 보이게 해줘.
```

**기대 출력**

- 우측 아티팩트 패널에 **매출 트리 + P&L 테이블 + 가정변수 패널**이 렌더됨

**확인할 것**

- "내가 채운 건 `D` 하나인데 `TREE`·`simCalc`·시뮬레이터가 **자동으로 채워졌다**"를 보여줌 — 이 장면이 데모의 절정임
- 트리 색이 토큰을 따르는지 봄 (매출 남색 / 비용 회색 / 이익 초록)
- 매출원이 빠짐없이 나오는지, Q와 P가 섞이지 않았는지 눈으로 검토함

**막히면**

- 아티팩트가 안 열리면 D 완성본 버전을 다시 렌더함

---

### Scene 6. 슬라이더로 흔들기 (3분)

**입력**

```text
시뮬레이터에서 테슬라 점유율과 Model 3/Y ASP를 낮춰보고,
에너지 가동률을 높여봤을 때 영업이익이 어떻게 바뀌는지 설명해줘.
```

**확인할 것**

- 점유율·ASP를 낮추면 Automotive 매출이 줄고, 같은 인도량 가정이 서비스·원가에도 반영되는지 봄
- "전환율이 1%p 낮으면?" 류의 투자심사 질문에 **같은 화면에서 즉시 답하는** 경험을 시연함

---

### Scene 7. Excel 전환 한 줄 마무리 (2분)

- HTML에서 구조가 합의되면, 같은 구조를 Excel 수식으로 **닫음** (발명 아님)
- Excel에서 수식·시트가 바뀌면 **BM md와 HTML도 같이 고침** — 세 산출물은 서로 검증하는 세 층임
- 단방향 흐름: BM md → HTML → IR JSON → Excel

---

## 4. 실패 대응 3단 (라이브 데모용)

1. 아티팩트 응답이 깨짐 → 미리 받아둔 **`D` 완성본**을 붙여넣어 Scene 5로 점프함
2. 그래도 막힘 → **Tesla 전사본**([conversation_transcript.md](../examples/Tesla/conversation_transcript.md))을 해설로 전환함
3. 시간이 밀림 → Scene 6(슬라이더)부터 생략함. Scene 1~5는 유지함

## 5. 수강생 실습 변형 (20분, 자기 회사로)

- 테슬라 대신 **자신이 아는 회사 1개**를 고름
- [templates/bm_brief.md](../course/templates/bm_brief.md)를 한 장 채움 (숫자 완벽할 필요 없음, 돈 버는 방식과 드라이버를 말로 적음)
- Claude에 넣고 **Scene 1~3만** 돌림 (매출원 분해 → Q×P → 공유 드라이버)
- 산출물: HTML 트리에 들어갈 **노드 목록**과 **공유 드라이버 1개**

## 6. 제출·평가 체크리스트

- [ ] BM 설명만으로 매출 구조가 이해됨
- [ ] 매출원이 Q×P 또는 퍼널로 분해됨 (Q와 P가 섞이지 않음)
- [ ] 비용이 매출 드라이버와 어떻게 연결되는지 설명됨 (공유 드라이버 1개 이상)
- [ ] 객관/주관 가정이 분리되고, 주관은 상/하한이 먼저 잡힘
- [ ] 같은 드라이버를 두 곳에서 따로 가정하지 않음 (이중 가정 0건)
- [ ] LLM 산출물을 사람이 검토·수정한 흔적이 있음
